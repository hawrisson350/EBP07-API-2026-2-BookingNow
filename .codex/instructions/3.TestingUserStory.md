# 3. Verificar una historia

Entrada: HU, analisis, implementacion y cambios de codigo.

1. Vincular cada criterio de aceptacion con una prueba o comprobacion.
2. Cubrir flujo esperado, datos invalidos, duplicados y relaciones cuando apliquen.
3. En operaciones protegidas, comprobar ausencia de JWT, JWT invalido/vencido
   y acceso a datos de otra identidad, segun el cambio.
4. Usar pruebas unitarias o de integracion segun lo que se deba demostrar.
   H2 verifica comportamiento local; no prueba compatibilidad PostgreSQL completa.
5. Ejecutar `.\mvnw.cmd verify` (Windows) o `./mvnw verify` (Linux/macOS).
   Registrar fallos, corregir los relacionados y repetir lo necesario.
6. Crear `stories/testing/HU-XXXXXX-testing.md`: comando, resultado, entorno,
   criterios cubiertos, pendientes y limitaciones. No copiar resultados antiguos
   como si pertenecieran a la ejecucion actual.
7. Marcar verificado solo lo respaldado por evidencia. Informar lo no ejecutado.

No solicitar acceso a servicios externos si el alcance actual es solo local.
