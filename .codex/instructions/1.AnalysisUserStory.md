# 1. Analizar una historia

Entrada: ficha en `stories/detail-user-stories/` y solicitud del equipo.

1. Leer la ficha, memoria y codigo relacionado. La HU contiene requisitos; el
   codigo muestra el comportamiento actual. No asumir que coinciden.
2. Identificar actor, datos, reglas, permisos, entidades y dependencias.
3. Comparar cada criterio con el codigo y detectar diferencias.
4. Registrar dudas que cambien contratos, autenticacion, datos o alcance.
   No inventar criterios ausentes. Avanzar en el analisis que no dependa de ellos.
5. Proponer cambios por capa hexagonal, endpoints y contrato de persistencia.
6. Asociar cada criterio con una comprobacion observable.
7. Crear `stories/analysis/HU-XXXXXX-analysis.md` usando su plantilla.

Si solo se solicita analisis, entregar el analisis sin modificar funcionalidad.
Si ya se solicito implementar y los requisitos son suficientes, continuar a la
siguiente etapa sin pedir una aprobacion adicional por este documento.
